Security

Your price history and positions are encrypted on your own computer and opened only in your own browser. The server in between, meaning us, cannot read the content. This page explains how that is achieved and where it ends.

In short

  • The key is the pairing code your browser creates in the lab. We have no copy of it.
  • The add-on encrypts and seals every packet before sending it. A packet whose seal does not match is not opened.
  • The server only stores encrypted packets briefly and deletes them after two hours at most.
  • The bridge add-on places no trades and does not read your account number or password.

The pairing code

The code is a 32-byte secret created with your browser's secure random number generator and starts with KLB1. It lives in two places: this browser's local storage and the add-on's settings in MT5. It is never sent to the server.

Three separate keys are derived from the code (with HMAC-SHA256): a channel number used to find packets, an encryption key that encrypts the content and a seal key that signs each packet. The server only sees the channel number; neither the code nor the other keys can be worked out from it.

Encryption and seal

  • Content is encrypted with AES-256 (CTR mode). Every packet gets a starting value that is never reused.
  • Every packet is sealed with HMAC-SHA256. The seal covers the channel number, the slot the packet belongs to and the encrypted content together.
  • The browser checks the seal first, then opens the packet. A packet that was altered, moved to another slot or sealed with another code is rejected.
  • Symbol names are encrypted too. The server cannot tell from a packet's name which symbol you follow.

The protocol has been written three times: in the MetaTrader 5 add-on, in the lab and in an independent reference implementation. Given the same input, all three produce byte-for-byte the same encrypted packet; this comparison is repeated by automated tests in every version.

The server checks a packet's format and keeps it in short-lived storage. Each packet is deleted on its own after two hours at most; when a newer one arrives, the old one is replaced at once. Packet contents are never written to logs. The number of packets a channel can write per minute is limited.

What the add-on reads

Kalibre Bridge only reads; it sends no orders, closes no positions and changes no settings. What it reads, encrypts and sends:

  • Closed candles of the symbols you choose: time, open, high, low, close, tick volume.
  • Open positions: symbol, side, lot, open time and price, current price, stop, target, profit and the position's magic number.
  • Your account currency, balance and equity.
  • Your broker's name, server name and whether the account is demo or live.

It does not read your account number, password, personal details or trade history. For the license check, the add-on sends your license key and MT5 account number to our license server; that request is separate from the encrypted data.

Limits of the protection

No system protects against everything. This one rests on these assumptions:

  • Whoever has your code can read your data. Do not share it. If in doubt, create a new code in the lab and paste it into the add-on; the old code stops working from then on.
  • Your device's security is yours. Someone with access to your computer or browser can also see decrypted data.
  • That traffic exists is not secret. The server sees how often and how large a channel's packets are. That shows usage, not content.

If you think you have found a security issue, please write to us.
